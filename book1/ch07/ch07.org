* Packages, Crates and Modules

All the previous programs were one module placed in one file. However, for
larger projects, programs should be split into multiple modules and multiple
files.

The Rust module system includes:
- Packages,
- Crates
- Modules,
- Paths

In this chapter all the above will be covered.

** Packages and Crates

A crate is the smallest amount of code that can be compiled to executable or
library. Previous one file programs that we wrote were crates. Crates can
contain modules (to be explained later).

Executable (binary crate) - stand alone compiled program, must have `main`
function (an entry point).

Library - no `main`, no executable, got functionality used by other programs.

Most often `crate` means library.

A package is a bundle of >= 1 crates with `Cargo.toml` file that describes how
to build them.

A package can contain >= 1 binary crates, but only 1 library crate. A package
must contain at least 1 crate (binary or library).

Using `cargo new my-project` creates new project, with the structure:

#+begin_src

.
├── Cargo.toml
└── src
    └── main.rs

2 directories, 2 files

#+end_src

`src/main.rs` is the crate root of a binary crate with the same name as the
package. If there were `src/lib.rs` then it would be a crate root for a library
crate with the same name as the package. Crate root files are passed to `rustc`
command under the hood for builds to complete.

A package with both `src/main.rs` and `src/lib.rs` has two crates (binary and
library). A package can have multiple binary crates by placing files in the
`src/bin/` (each file here is a separate binary crate).
